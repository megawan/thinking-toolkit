# Case study: A software team's onboarding objective

> Illustrative scenario. It is a composite written to show the method in use, not a report about a real organisation.

Method: [OKR](../methods/planning/okr.md)

## Context

A software company saw many new customers drop off in the first week. The team had several improvement projects but no shared target.

## What was done

- The objective was 'Make onboarding delightful for new customers'
- Key results: activation from 35 to 50 percent, median time to first project from 3 days to 1 day, new-user satisfaction score from 20 to 35
- Initiatives: a guided setup checklist, templates and a personal welcome message
- At mid-quarter activation and time to first project were on track but satisfaction had not moved; support replies turned out to be slow, so an initiative was added

## Outcome

At the end activation reached 48 percent (about 0.85), time to first project reached 1 day (1.0) and satisfaction 28 (about 0.5), an average of about 0.78. The team kept the objective for the next quarter and focused on support.

## Lessons

- Weekly check-ins caught the lagging key result in time to act
- Measuring outcomes, not launches, redirected effort
- A score below 1 on an ambitious key result is information, not failure
