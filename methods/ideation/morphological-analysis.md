# Morphological Analysis

> Break a problem into its parameters, list the options for each, and combine them to find designs you would not have thought of.

| | |
| --- | --- |
| **Category** | Idea generation |
| **Time needed** | 45-90 minutes, solo or in a small group |
| **Best for** | Designing products, services, or plans that have several independent choices |

## What it is

Morphological analysis was developed by the Swiss astrophysicist Fritz Zwicky in the 1940s. The core tool is a **morphological box** (or Zwicky box), a table with one row for each important parameter of the problem and, in each row, the possible options for that parameter. A complete solution is one option from each row.

If there are four parameters with four options each, there are 4 x 4 x 4 x 4 = 256 combinations. Many are poor, some are impossible, and a few are surprising and good.

## Why it works

People tend to design by adjusting a favourite solution, so many combinations never get considered. Splitting the problem into parameters makes the structure visible, and combining options systematically produces designs a free brainstorm would miss. It also makes you list every option for each parameter, including those you would normally dismiss.

## When to use

- The problem has several separate design choices
- You want to explore the whole space of options before settling
- An established solution feels like the only possible one
- A team must design a product, service, or event from scratch

## When not to use

- The problem is a single choice; use a list or [Decision Matrix](../decision-making/decision-matrix.md)
- Parameters depend heavily on one another; combining them gets confusing
- You need only a quick idea; try [Crazy 8s](crazy-8s.md)

## How to apply

1. **State the problem** in one sentence.
2. **Identify the parameters.** Which independent features or decisions define a solution? Aim for four to seven.
3. **Check independence.** If two parameters always move together, merge them.
4. **List options per parameter.** Write as many as you can, including unusual ones. Aim for at least three to five each.
5. **Draw the box.** One row per parameter, options across the row.
6. **Combine.** Pick one option from each row to form a candidate solution. Trace a path through the box. Try obvious combinations, random ones, and the odd ones.
7. **Remove impossible pairs.** Mark combinations that cannot work together.
8. **Evaluate.** Shortlist three to five promising combinations, then compare them with criteria, for example in a [Decision Matrix](../decision-making/decision-matrix.md).
9. **Develop and test** the best one.

## Example: designing a local food-delivery service

**Problem:** Design a food-delivery service for a small town.

| Parameter | Option 1 | Option 2 | Option 3 | Option 4 |
| --- | --- | --- | --- | --- |
| What is delivered | Ready meals | Fresh ingredients | Meal kits | Groceries |
| Who delivers | Own staff | Volunteers | Taxi drivers | Customers collect |
| How to order | App | Phone call | Weekly subscription | Messaging chat |
| When | On demand | Fixed daily slot | Weekly | Pre-ordered |
| Pricing | Per order | Subscription | Free above a limit | Pay what you want |

**Combinations explored:**

- Meal kits, delivered by own staff, ordered by subscription, weekly, priced as a subscription. Fits busy families.
- Ready meals, delivered by taxi drivers, ordered by chat, in fixed daily slots, priced per order. Uses spare taxi capacity without hiring drivers.
- Groceries, collected by customers, pre-ordered by phone, daily slots, free above a limit. Suits older customers and needs no delivery.

**Result:** The taxi-driver combination was one the team had not considered. They test it for a month in one neighbourhood.

## Tips

- Use a spreadsheet or sticky notes so rows and options are easy to change
- Add a "none" or "other" cell to prompt unusual options
- Colour-code combinations that look strong
- If the box is too large, fix two or three parameters first and vary the rest

## Pitfalls

- **Too many parameters.** The number of combinations grows quickly, and the box becomes unusable.
- **Overlapping parameters.** They should be independent where possible.
- **Few options per row.** A box with two options per row adds little over a normal choice.
- **Skipping the unusual.** The unexpected combinations are the point.
- **Not evaluating.** The box produces candidates, not decisions.
- **Treating the box as final.** Update it as you learn more.

## Quick checklist

- [ ] Problem stated
- [ ] 4-7 independent parameters
- [ ] Several options per parameter
- [ ] Combinations tried, including odd ones
- [ ] Impossible pairs removed
- [ ] Shortlist evaluated against criteria
