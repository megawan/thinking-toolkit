# How Might We

> Turn a problem into an open, hopeful question so your team starts with ideas instead of excuses.

| | |
| --- | --- |
| **Category** | Idea generation |
| **Time needed** | 15-30 minutes, solo or in a group |
| **Best for** | The start of a brainstorm, design project or workshop, when a problem needs framing |

## What it is

"How might we...?" (HMW) is a way of phrasing a challenge as a question. The format is associated with Min Basadur's work at Procter & Gamble in the 1970s and was popularised by IDEO and the Stanford d.school.

Each word does a job:

| Word | Effect |
| --- | --- |
| How | Assumes a solution exists; the question is how to find it |
| Might | Invites possibilities; an idea does not have to work or be final |
| We | Makes it shared; the team solves it together |

## Why it works

The way a problem is stated shapes the ideas that follow. "Users hate our checkout" invites blame; "How might we make paying feel effortless?" invites options. A well-framed question is open enough to allow varied answers and narrow enough to give direction.

## When to use

- At the start of a brainstorm or design project
- After research, to turn findings into opportunities
- When a team is stuck in complaints about a problem
- To prepare a question for [Brainwriting 6-3-5](brainwriting-635.md) or [Crazy 8s](crazy-8s.md)

## When not to use

- The problem has a known solution that only needs executing
- You have not yet understood the problem; research or use [Five Whys](../root-cause/five-whys.md) first
- You need a diagnosis, not options

## How to apply

1. **Gather insights.** Write down what you know about the problem, who is affected, and what they need.
2. **Spot the tension.** Where do needs conflict or go unmet? Each tension is a seed for a question.
3. **Write several HMW questions** for each insight. Aim for at least five per insight.
4. **Vary the scope.** Write some broad, some narrow.
5. **Check each question** against the tests below.
6. **Cluster and choose.** Group similar questions and pick one to three that you can start on.
7. **Use them.** Take the chosen questions into a brainstorm.

## Getting the scope right

| Too narrow | Good | Too broad |
| --- | --- | --- |
| How might we add a progress bar to the checkout? | How might we make checkout feel quick and predictable? | How might we fix online shopping? |
| How might we put a bigger button on the form? | How might we help people finish the form without help? | How might we eliminate all customer problems? |

## Tests for a good question

- Does it avoid a built-in solution?
- Does it allow at least several different answers?
- Is it focused on a person, a need or a situation?
- Does it feel both exciting and doable?
- Is it positive in tone, not blaming?

## Ways to reframe a problem

| Technique | Example |
| --- | --- |
| Amplify the good | The queue moves fast at the start; how might we make the whole queue feel like that? |
| Remove the bad | How might we remove the need to register before ordering? |
| Explore the opposite | How might we make people want to wait? |
| Question an assumption | If customers did not need to visit the office, how might we deliver the service? |
| Change the user | How might we make this work for someone who has never used a computer? |
| Break it into parts | How might we make signing up quick? How might we make the first week welcoming? |

## Example: a library with falling visits

**Observation:** Visits to a neighbourhood library have dropped by a third. Young adults rarely come.

**Insights:** Young adults want a quiet place with power and Wi-Fi. They think the library is for children. They do not know about the events held there.

**Questions:**

- How might we make the library the best study spot in the area?
- How might we show young adults that the library is for them?
- How might we let people discover events without visiting?
- How might we turn the library into a place to meet people, not only to borrow?

**Choice:** The team picks the first and second questions and takes them into a brainwriting session.

## Pitfalls

- **Hiding a solution in the question.** "How might we build an app for X?" already decides the answer.
- **Too broad.** "Fix education" gives no direction.
- **Too narrow.** The question allows only one answer.
- **Negative framing.** Blame produces defensive ideas.
- **Writing only one question.** Write many and choose.
- **Skipping insights.** Without them, questions are guesses.

## Quick checklist

- [ ] Insights and tensions listed
- [ ] Multiple HMW questions per insight
- [ ] Scope varied
- [ ] No solution hidden inside
- [ ] One to three questions chosen
- [ ] Questions taken into an idea session
